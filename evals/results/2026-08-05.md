## On sourcing more realistic example material (issue #7's second ask)

Investigated `openmainframeproject/cobol-programming-course` as a source of
fetch-on-demand fixtures, since real client source isn't always available to
test against. Findings:

- It contains full COBOL programs (procedural logic) and real JCL, but **no
  Natural, Mantis, Adabas, or Supra source** — those are proprietary Software AG
  4GLs with no public open-source example corpus. This tool's core dialects
  (`natural.py`, `mantis.py`, `adabas.py`, `supra.py`) cannot be hardened against
  it; there is currently no way to source more realistic fixtures for them short
  of a real (anonymised) client engagement.
- It **does** contain real JCL and some DB2 DDL setup (`CRETBL.jcl`,
  `DB2SETUP.jcl`), which overlaps with `environment.py`'s `jcl` and `sql_ddl`
  dialects. Fetching a handful of those on demand as *supplementary, non-golden*
  fixtures is feasible and would genuinely harden the JCL scanner against
  real-world variety beyond the one synthetic `MMB0100.jcl` fixture — but it's a
  different, smaller piece of work than "a more robust example suite" for the
  tool as a whole, and it's scoped as its own follow-up rather than folded into
  this eval run (see issue #13).
- Not pursued: pulling full `.cbl` programs in as fixtures for anything, since
  this tool does not parse COBOL procedural logic at all, only copybook-shaped
  data layouts (`cobol_copybook` in `environment.py`) — and this repo's `.cbl`
  files didn't contain standalone `.cpy` copybooks to test that scanner against
  either.
