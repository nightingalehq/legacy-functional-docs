# MMP0100 — Mill order release to production

## Purpose

MMP0100 decides whether a mill order (`MILL-ORDER`) can be released to production, based on whether enough stock of the required steel grade (`GRADE-CODE`) is available at the requested plant *(inferred from the branching structure across [[MMP0100:33-60]] — the header comment at [[MMP0100:2]] states this same purpose but is treated as an unverified lead, not evidence)*. Depending on stock availability it marks the order fully released (`RLSD`), partially released (`PART`), or leaves it unchanged and returns a rejection code [[MMP0100:52-60]].

## Business rules

1. **Order must exist** (MMP0100:BR-001) — If no `MILL-ORDER` record is found for `#ORDER-NO` [[MMP0100:34]], the module sets `#RETURN-CODE` to 10 (MMP0100:BR-002) [[MMP0100:35]] and stops processing (MMP0100:BR-003) [[MMP0100:36]].

2. **Order must be confirmed before release** (MMP0100:BR-004) — If the mill order's status is not `CONF` (confirmed) [[MMP0100:38]], the module sets `#RETURN-CODE` to 20 (MMP0100:BR-005) [[MMP0100:39]] and stops processing (MMP0100:BR-006) [[MMP0100:40]].

3. **Only matching steel grade is considered** (MMP0100:BR-007) — While scanning stock balances, any record whose steel grade does not match the order's requested grade is skipped and the loop moves on to the next stock record (MMP0100:BR-008) [[MMP0100:44-45]]. *(The 2003 header comment claims a "grade substitution check" was added here [[MMP0100:4]], but the code only skips non-matching grades rather than substituting one grade for another — this is a discrepancy between the comment and the code; see SME questions.)*

4. **Only stock at the requested plant counts** (MMP0100:BR-009) — Stock is only accumulated toward availability when its plant code matches `#PLANT` [[MMP0100:47]] *(inferred — the brief does not show what happens to `#AVAIL-TOTAL` inside this condition, only that the plant match is tested; confirm the accumulation logic)*.

5. **Release decision on available stock** (MMP0100:BR-010) — Once stock has been totalled, the module evaluates three outcomes in order [[MMP0100:52]]:
   - **Full release**: if total available stock (`#AVAIL-TOTAL`) is at least the ordered weight (MMP0100:BR-011) [[MMP0100:53]], the order status is set to `RLSD` (released to production) (MMP0100:BR-012) [[MMP0100:54]].
   - **Partial release within tolerance**: otherwise, if available stock is at least the ordered weight reduced by `#TOLERANCE-PCT` percent (MMP0100:BR-013) [[MMP0100:55]], the order status is set to `PART` (partially released) (MMP0100:BR-014) [[MMP0100:56]] and `MMN0250` is invoked with the order number, available total, and return code [[MMP0100:57]] *(the effect of this call cannot be verified — `MMN0250`'s source was not supplied; unresolved)*.
   - **Insufficient stock**: otherwise (MMP0100:BR-015) [[MMP0100:58]], `#RETURN-CODE` is set to 30 (MMP0100:BR-016) [[MMP0100:59]] and the module stops without changing the order (MMP0100:BR-017) [[MMP0100:60]].

## Processing sequence

1. Find the mill order matching `#ORDER-NO` [[MMP0100:33]]; if none is found, return code 10 and stop [[MMP0100:34-36]].
2. Check the order's status is `CONF`; if not, return code 20 and stop [[MMP0100:38-40]].
3. Read stock balances by grade code, starting from the order's grade [[MMP0100:43]], skipping any record for a different grade [[MMP0100:44-45]] and accumulating available stock at the requested plant [[MMP0100:47]].
4. Decide the release outcome — full release, partial release, or rejection — based on available stock versus ordered weight and tolerance [[MMP0100:52-60]].
5. On full or partial release, update the mill order's status [[MMP0100:63]] and commit [[MMP0100:64]].
6. Call `MMN0900` with the order number and plant [[MMP0100:67]] *(purpose not determinable — source not supplied; unresolved)*.
7. Perform the internal `WRITE-AUDIT` subroutine, which stores an `ORDER-AUDIT` record [[MMP0100:68]], [[MMP0100:71]], and commits [[MMP0100:72]].
